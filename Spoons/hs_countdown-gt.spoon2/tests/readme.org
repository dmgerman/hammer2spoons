#+title: hs_countdown-gt's tests

These are the tests of hs_countdown-gt. They run inside the running Hammerspoon 2, on a fresh copy
of the Spoon. They are marked =export-ignore=, so users who install the Spoon do not download them.

The harness, the runner, the test windows, the makefile and the self-tests are copies of the
files in =tests-common/= at the top of the repository. They are never edited here.
=tests-common/readme.org= explains how they are kept the same, and hs_window-gt's
=tests/readme.org= describes how a run works and everything a test receives.

* Running the tests

#+begin_src sh
make test                                          # every tests/*.test.js, without choosers
tests/run tests/selftest/harness.test.js           # the given files, asking on screen first
#+end_src

Run only the files a change can affect.

* =tests/start.test.js= and issue 432

Running =tests/run tests/start.test.js= crashed Hammerspoon 2 until upstream fixed [[https://github.com/Hammerspoon/Hammerspoon2/issues/432][issue 432]],
in pull request #435. The alerts the file shows stacked taller than the screen, and AppKit threw an
=NSGenericException= inside a text prompt's modal loop while it laid out the alert stack window.
On 2026-11-23, with a build that includes the fix, the file passed and Hammerspoon 2 did not crash.

* The copy under test

The Spoon writes no files, so the copy needs no =tests/spoon.js=. Its =start()=, which the harness
calls, adds its own menu bar item and progress bars, beside the user's. Its =stop()=, which the
harness calls at the end, stops a running countdown and removes both.

* What is not tested

Every statement of the Spoon's readme has a test, except the ones below. Each is listed with the
reason it has none. =tests/readme-review.test.js= holds the tests added when the readme was read
as a whole against the others.

1. *The bars rebuilt when a display is connected, disconnected or resized.* A test cannot connect
   or disconnect a display, and resizing one would rearrange the user's windows.
2. *The notification needing the Notifications permission.* The tests record the notification
   instead of sending it, so that none reaches the user, and a test cannot take the permission
   away.
3. *The menu included as a submenu with =children:=.* Showing a submenu is hs_menu-gt's work, and
   its own tests cover it. The tests here check that =menu= is the menu =menuShow()= displays.
4. *Installing.* =hs.spoons.use()= downloads the Spoon from GitHub. The tests load a copy of the
   Spoon from this directory instead. The =hotkeys= option calls =bindHotkeys()=, which has a test.
5. *The sections that only describe:* "Credits" and "Requirements". Each requirement they name
   has a test of its own, except the Notifications permission, for the reason in item 2.

* Cancelling a prompt

A test cancels a prompt with the fixture's =promptCancel()=, called before the function that
prompts. A prompt of hs_interactive-gt is modal, and no promise of a test resolves while it is
open, so =promptCancel()= works from =hs.timer= callbacks. In the user's configuration, closing a
dialog with Escape takes two presses, so it sends a second Escape when the prompt is still open
after the first. A prompt that a test answers is answered the same way, from a timer set before it
opens, as =promptAnswer()= in =tests/start.test.js= does.
