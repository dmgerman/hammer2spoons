#+title: hs_appleMusic-gt's tests

These are the tests of hs_appleMusic-gt. They run inside the running Hammerspoon 2, on a fresh
copy of the Spoon. They are marked =export-ignore=, so users who install the Spoon do not download
them.

The harness, the runner, the test windows, the makefile and the self-tests are copies of the
files in =tests-common/= at the top of the repository. They are never edited here.
=tests-common/readme.org= explains how they are kept the same, and hs_window-gt's
=tests/readme.org= describes how a run works and everything a test receives.

* Running the tests

#+begin_src sh
make test                                          # every tests/*.test.js, without choosers
tests/run tests/selftest/harness.test.js           # the given files, asking on screen first
#+end_src

Run only the files a change can affect.

* The copy under test

=tests/spoon.js= points the copy's =albumListPath= into the run's directory, so that the user's
=albums.txt= is never read or written. =tests/protection.test.js= checks it.

The copy's =start()= only checks that hs_interactive-gt and hs_menu-gt are loaded. Nothing
touches the Music application until a test calls a function that does.

* Skipping to another album

=tests/skipping.test.js= uses what Music is playing, such as a playlist, which Music continues
with another album. Music's Previous does not reach its History, so an album played earlier cannot
be used. The test reads the album that follows from Music's queue panel, through the Accessibility
API, and is skipped when none follows. It skips forward into that album and back, then plays the
user's track again from its start and puts back whether Music was playing. An alert names each
step as it starts.

* Auto-play

=tests/autoplay.test.js= neither stops nor plays Music. It posts Music's playerInfo notification
itself, with =hs.distributednotifications.post()=, and answers the Spoon's question about the
player state in place of Music. The album list is an empty file, so when auto-play acts it reports
that the list is empty and turns itself off, and the tests look for that alert. A posted
notification reaches every application, so another application that listens to Music also
receives these.

* Playing an album

=tests/playing.test.js= plays Kind of Blue with /Random album/, In a Silent Way with /Choose
album/, and Meddle with =albumPlay()=, each through the album's page and its Play button. Each
replaces what Music was playing, and Music's scripting cannot return to a playlist afterwards; the
volume, and whether Music was playing, are put back. Run it only when the user agrees.
