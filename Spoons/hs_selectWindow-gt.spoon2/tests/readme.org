#+title: hs_selectWindow-gt's tests

These are the tests of hs_selectWindow-gt. They run inside the running Hammerspoon 2, on a fresh
copy of the Spoon. They are marked =export-ignore=, so users who install the Spoon do not download
them.

The harness, the runner, the test windows, the makefile and the self-tests are copies of the
files in =tests-common/= at the top of the repository. They are never edited here.
=tests-common/readme.org= explains how they are kept the same, and hs_window-gt's
=tests/readme.org= describes how a run works and everything a test receives.

* Running the tests

#+begin_src sh
make test                                          # every tests/*.test.js, without choosers
tests/run tests/selftest/harness.test.js           # the given files, asking on screen first
#+end_src

Run only the files a change can affect.

* The copy under test

The Spoon writes no files, so the copy needs no =tests/spoon.js=.

The copy uses the user's hs_interactive-gt, hs_window-gt and hs_windowfilter-gt, which the
configuration has loaded. Its =start()=, which the harness calls, creates a filter on the user's
hs_windowfilter-gt. Its =stop()=, which the harness calls at the end, closes its chooser,
destroys that filter and releases its keys.

* The tests of the chooser

=tests/chooser.js= holds the helpers that =tests/chooser.test.js= and =tests/settings.test.js=
share.

The chooser lists the user's windows as well as the test windows. The tests look only at the
rows of the test windows, found by their titles, and their messages never show the title of one
of the user's windows. A test that needs the test windows alone restarts the copy with every
other running application in =skipApplications=, and restores the setting when it ends.

The copy reports its chooser as a prompt of the user's hs_interactive-gt. Keys are sent one at a
time, each only while the copy's chooser is visible and a prompt is reported open, so that a key
never reaches the application behind the chooser.

* What is not tested

Every statement of the Spoon's readme has a test, except the ones below. Each is listed with the
reason it has none. =tests/readme-review.test.js= holds the tests added when the readme was read
as a whole against the others.

1. *=applicationByBundleSelect()= switching to and from an application.* The test windows belong
   to =osascript=, which has no bundle identifier, so they cannot be found by one. The tests
   cover an application that is not running, and the alerts for a missing identifier and a bad
   pattern.
2. *=thumbnailTopRatio=.* It places the thumbnail only when the chooser's window cannot be
   found among Hammerspoon 2's windows, which happens only in the moment before the chooser is
   shown.
3. *=persistentThumbnailCache=.* It makes a thumbnail appear sooner the next time the chooser
   opens. The tests cannot tell a kept snapshot from a new one, because both are drawn the same
   way, and the time a snapshot takes varies too much to tell them apart by speed.
4. *=fullscreenScreenSkip= with one screen.* The tests of =fullscreenScreenSkip=, in
   =tests/two-screens.test.js=, need at least two screens, and a screen cannot be disconnected
   during a run.
5. *A chooser without the Screen Recording permission.* The permission cannot be withdrawn
   during a run; System Settings changes it, and macOS asks for it again afterwards.
6. *A snapshot kept while the chooser is open.* Selecting a window again draws its kept
   snapshot, which the tests cannot tell from a new one, for the reason given in 3.
7. *Installing.* =hs.spoons.use()= downloads the Spoon from GitHub. The tests load a copy of the
   Spoon from this directory instead.
8. *The sections that only describe:* "Examples", "Limitations", "Coming from Hammerspoon 1" and
   "Requirements". Each function and requirement they name has a test of its own.
