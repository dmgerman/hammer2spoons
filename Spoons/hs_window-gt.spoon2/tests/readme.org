#+title: hs_window-gt's tests

These are the tests of hs_window-gt. They run inside the running Hammerspoon 2, because most of
the Spoon acts on real windows and screens. They are marked =export-ignore=, so users who install
the Spoon do not download them.

* Running the tests

The tests are run from the Spoon's directory, with Hammerspoon 2 running and =hs.ipc= started:

#+begin_src sh
make test                                     # every tests/*.test.js
make test TESTS="tests/selftest/*.test.js"    # the given files
#+end_src

Hammerspoon 2 first shows a chooser asking whether to start. The tests move windows and the
pointer, so the mouse and the keyboard are left alone from the start until the alert with the
totals appears. =tests/run= then prints one line per test and exits with 0 when every test passed
or was skipped, 1 when a test failed or the run was cancelled, and 2 when the tests could not be
run or did not finish within =HS_WINDOW_TESTS_TIMEOUT= seconds (600 by default).

The tests in =tests/selftest/= check the harness itself. Two of them fail on purpose.

* How a run works

A run has four steps:

1. =tests/run= sends one line through =hs2=, which loads =tests/harness.js= and calls its
   =run()=. =hs2= does not wait for a promise, so =run()= returns at once and the tests continue
   inside Hammerspoon 2.
2. The harness loads a fresh copy of the Spoon from =../init.js=. =require()= caches a module
   under the path it was given, and the configuration loads the Spoon through its link in
   =Spoons/=, so this copy has its own state and its own =config=. Its =attachFile= and
   =screenshotDir= point into a temporary directory, so it never reads or writes the user's
   attached keys. The harness starts the copy before the tests and stops it afterwards.
3. Each test runs in turn. A test that takes longer than its timeout fails.
4. The harness writes a report, and =tests/run= prints it. The temporary directory is removed.

* Writing a test

A test file is named =<area>.test.js= and exports a list of tests. Each test has a =name=, a
=run= function, and optionally a =timeout= in seconds, which is 10 by default. =run= may be
asynchronous, and receives one argument with these fields:

| Field         | Holds                                                                      |
|---------------+----------------------------------------------------------------------------|
| =spoon=       | The fresh copy of hs_window-gt                                             |
| =dir=         | The temporary directory of the run                                         |
| =runId=       | A number unique to the run, which is part of every test window's title     |
| =assert=      | =ok(value, message)=, =equal(actual, expected, message)=, =fail(message)= and =frameEqual(actual, expected, message)= |
| =skip=        | =skip(reason)= ends the test and reports it as skipped                     |
| =wait=        | =wait(seconds)= returns a promise that resolves after that many seconds    |
| =windowsOpen= | =windowsOpen(count)= opens that many test windows, 1 by default, and resolves to their =HSWindow= objects |
| =frameSet=    | =frameSet(window, frame)= sets a window's frame and waits for it to take effect |
| =screenFrame= | =screenFrame(window)= returns the usable frame of the window's screen      |
| =screensNeed= | =screensNeed(count)= ends the test as skipped when fewer screens are connected |
| =alertsCapture= | =alertsCapture()= returns a list that receives the message of every alert shown until the test ends. The alerts are still shown. |
| =promptCancel= | =promptCancel()= waits for a prompt of hs_interactive-gt to open and cancels it with Escape. It is called without =await=, before the function that prompts. |

#+begin_src js
module.exports = [
    {
        name: "leftHalf places the window on the left half of its screen",
        run: async (t) => {
            // ...
            await t.wait(0.3)
            t.assert.equal(window.frame.x, screen.x)
        }
    }
]
#+end_src

A test acts only on windows it opens with =windowsOpen()=. The Spoon's internal functions are
tested through the exported functions that use them.

* The test windows

=windowsOpen()= starts =tests/fixture-windows.jxa= with =osascript -l JavaScript=. That script
opens one plain Cocoa window for each title it is given and keeps them open until its process
ends. The harness ends the process after each test, also when the test fails or times out, so
a test does not close its own windows.

The windows belong to a separate process rather than to Hammerspoon 2, for one reason.
hs_windowfilter-gt leaves Hammerspoon 2's own windows out of its default filter, which
hs_window-gt uses. A window made with =hs.ui.window()= can be moved, but the Spoon would receive no
event when it is focused, moved or closed.

Three measurements, made on 2026-11-23, govern how frames are compared and chosen:

1. A window rounds each value of its frame to a whole point, and a value can move by up to one
   point in doing so: y = 200.25 was read back as 201. =assert.frameEqual()= therefore accepts
   a difference of 1 point in each value.
2. A test window cannot be smaller than 87 by 33 points, so a test does not ask for less.
3. The windows appear about 0.3 s after their process starts. =windowsOpen()= waits up to 5 s.

Expected frames are computed from =screenFrame()=, never from the size of one display. A test that
needs two screens calls =screensNeed(2)= first.
