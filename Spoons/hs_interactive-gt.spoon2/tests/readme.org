#+title: hs_interactive-gt's tests

These are the tests of hs_interactive-gt. They run inside the running Hammerspoon 2, on a fresh
copy of the Spoon. They are marked =export-ignore=, so users who install the Spoon do not
download them.

The harness, the runner, the test windows, the makefile and the self-tests are copies of the
files in =tests-common/= at the top of the repository. They are never edited here.
=tests-common/readme.org= explains how they are kept the same, and hs_window-gt's
=tests/readme.org= describes how a run works and everything a test receives.

* Running the tests

#+begin_src sh
make test                                          # every tests/*.test.js, without choosers
tests/run tests/selftest/harness.test.js           # the given files, asking on screen first
#+end_src

Run only the files a change can affect.

* The copy under test

The harness calls the copy's =init()=, which defines its built-in commands in the copy's own
registry, and its =stop()= at the end, which releases the keys the copy bound. The copy shares
nothing with the user's copy: its commands, key bindings, command order and prompt state are its
own. =t.spoon= is the copy; =hs.spoons["hs_interactive-gt"]= is the user's, which the harness's
own choosers use.

Three things need care:

1. *Keys.* A test binds keys only with ctrl-alt-shift and the digits 7, 8 and 9, which the user
   does not bind, and presses one only after the copy has bound it, so that its hotkey takes the
   press.
2. *Loading Spoons.* =use()= loads Spoons with =hs.spoons.load()=. Its tests replace
   =hs.spoons.load= for the length of a test with a loader of test Spoons made in memory, so
   that no Spoon of the user's is loaded.
3. *Prompts.* A test that opens a chooser or a dialog answers or cancels it itself, with keys.
   It waits on the copy's own =promptIsOpen()=: the fixture's =t.promptCancel()= watches the
   user's hs_interactive-gt, not the copy. Typed text is sent one character at a time, checking
   before each key that the prompt is still open, because a key sent after a chooser closed
   reaches the application behind it. A dialog is answered from a timer set before it opens.

* What the tests do not cover

Every statement of the Spoon's readme has a test, except these, checked on 2026-11-23:

1. *Where Spoons are looked for.* =use()= loads with =hs.spoons.load()=, whose search of the
   configuration's =Spoons= directory is Hammerspoon 2's behaviour. The tests replace
   =hs.spoons.load= so that no Spoon of the user's is loaded, and check only that =use()= calls
   it with the Spoon's name.
2. *=keySet()= returning null when macOS refuses a key.* A test cannot make macOS refuse a key.
3. *A hotkey without a reference being garbage-collected.* This is Hammerspoon 2's behaviour,
   and depends on when the collector runs.
4. *0.05 seconds of =runDelay= being enough.* The tests check that a command runs after its
   =runDelay=, not that 0.05 seconds avoids the focus problem the readme describes, which
   depends on timing that varies.
5. *The screenshot of the command chooser, and the dialog for =countdown-start-for=.* These are
   images.

One difference is not covered by the readme either way: a command's =interactive= entry without
a =reader= makes the command fail with "was given a reader object", while
=interactiveFunctionCreate()= passes such an argument on unchanged.
