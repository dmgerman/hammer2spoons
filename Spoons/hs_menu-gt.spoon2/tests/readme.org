#+title: hs_menu-gt's tests

These are the tests of hs_menu-gt. They run inside the running Hammerspoon 2, on a fresh copy of
the Spoon. They are marked =export-ignore=, so users who install the Spoon do not download them.

The harness, the runner, the test windows, the makefile and the self-tests are copies of the
files in =tests-common/= at the top of the repository. They are never edited here.
=tests-common/readme.org= explains how they are kept the same, and hs_window-gt's
=tests/readme.org= describes how a run works and everything a test receives.

* Running the tests

#+begin_src sh
make test                                          # every tests/*.test.js, without choosers
tests/run tests/selftest/harness.test.js           # the given files, asking on screen first
#+end_src

Run only the files a change can affect.

* The copy under test

=tests/spoon.js= points the copy's =cacheDir= into the run's directory, so that the options it
draws are saved there and =diskCacheClear()= empties only that directory. =iconDir= is only read,
so the user's icons are used as they are.

The copy binds its keys only while one of its menus is shown, and =stop()=, which the harness
calls at the end, hides that menu and ends the copy's subscription to the user's
hs_interactive-gt's prompt notices.

A test that shows a menu sends its keys only while the copy reports the menu shown, one key at a
time, because a key sent after the menu closed would reach the application behind it.

The tests of the on-screen menu, in =tests/onscreen.test.js=, also check that a test window has the
focus before each key, so that a key the copy does not take reaches that window. The test of the
mouse clicks only where a test window is beneath the menu, and the fixture puts the pointer back
at the end of the test.

The tests of prompts, in =tests/onscreen.test.js= and =tests/presenter.test.js=, tell the user's
hs_interactive-gt that a prompt opened and closed, with =promptOpened()= and =promptClosed()=,
because the copy listens to the user's hs_interactive-gt. No prompt is shown, and a test that
fails still reports the prompt closed.

The panel is found among the recorded canvases by its position. The Spoon draws each option in a
canvas of its own at (0, 0), which is never shown, while the panel is centred on a screen.

* What is not tested

Every statement of the Spoon's readme has a test, except the ones below. Each is listed with
the reason it has none.

1. *The Stream Deck.* Its presenter is in hs_streamdeck-gt, which is not published here. The
   tests of =navigate= and =keepOpen= on a presenter that cannot hide stand in for it.
2. *Installing.* =hs.spoons.use()= downloads the Spoon from GitHub. The tests load a copy of the
   Spoon from this directory instead.
3. *Options with =fn:=, =app:= or =url:= without hs_interactive-gt.* The tests run in the user's
   Hammerspoon 2, which has hs_interactive-gt loaded, and the copy reads that one.
4. *The examples.* "A first menu", "Actions", "Example: a window menu" and the examples of
   =keepOpen= bind keys or call the user's commands and hs_window-gt. Each field they use has a
   test of its own.
5. *A command with a text prompt blocks Hammerspoon 2.* This is how =hs.ui.textPrompt= works,
   not something this Spoon does. hs_interactive-gt's tests cover its prompts.
6. *What a picture looks like.* The tests check that an option is drawn, at what size, and
   whether it is saved. They do not check its pixels, because =HSImage= cannot compare two
   images. This covers:
   - the wrapping, shrinking and shortening of a label, with =labelSize= and =labelSizeFloor=;
   - =iconScale= and =iconScaleAlone=;
   - the recolouring of an SF Symbol in =symbolColor=;
   - the question mark drawn for an icon that cannot be loaded and an option without a label;
   - the image being twice the tile size in pixels.
7. *The warning about a font that is not installed.* Hammerspoon 2 writes it to its own console,
   which JavaScript cannot read. The test checks that the option is still drawn.
8. *=config.screen.level=.* A canvas does not report its window level.
9. *How long drawing takes.* The readme says a few milliseconds. The tests do not measure time.
