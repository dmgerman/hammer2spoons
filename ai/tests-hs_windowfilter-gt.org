#+title: Notes for hs_windowfilter-gt's tests

These are the measurements and decisions of the tests of hs_windowfilter-gt, epic
hammer2spoons-atg. =Spoons/hs_windowfilter-gt.spoon2/tests/readme.org= describes the tests.

* How long each event takes (hammer2spoons-atg.2)

Measured on 2026-11-23 through =hs2=, with one test window from =tests-common/fixture-windows.jxa=
and a filter of the user's loaded copy that allowed only that window, destroyed afterwards. The
debounce settings were at their defaults: =moveDebounce= 0.1, =titleDebounce= 0.1,
=stateDebounce= 0.08. Times are from the call to the event.

| Change                     | Events                                                             | ms      |
|----------------------------+--------------------------------------------------------------------+---------|
| window opened              | windowAllowed, windowCreated                                       | 335     |
| frame changed              | windowMoved, windowResized                                         | 110     |
| size changed               | windowResized                                                      | 111     |
| =focus()=                  | windowFocused                                                      | 74      |
| =minimize()=               | windowNotVisible, windowNotOnScreen, windowMinimized               | 359     |
| =unminimize()=             | windowVisible, windowOnScreen, windowUnminimized                   | 252     |
| application =hide()=       | windowNotOnScreen, windowUnfocused, windowHidden, windowNotVisible | 19 to 22 |
| application =unhide()=     | windowVisible, windowOnScreen, windowUnhidden                      | 7       |
| close button               | windowDestroyed                                                    | 22      |

The opening time includes the window process starting. The recorder therefore waits up to 2 s
for an event, which is more than five times the slowest.

* Changing a window's title

A test window's =AXTitle= is not settable: =isAttributeSettable("AXTitle")= returned false, so
the title cannot be changed through =hs.ax=. The window process now reads a command file every
0.1 s, through an =NSTimer= block in the JXA script, and =t.windowTitleSet()= writes the command
=title <n> <text>= into it. A probe changed a title this way within 0.5 s.

* Closing windows a test left hidden or minimized

The shared fixture now unhides the application and unminimizes the windows before closing them
with their close button. Without it, a test that fails with a window minimized or hidden would
leave that window to be closed by ending its process, which produces no windowDestroyed, and the
window would stay in the user's hs_windowfilter-gt's list.

* What a fresh copy costs (hammer2spoons-atg.7)

Measured on 2026-11-23 through =hs2=, with a fresh copy loaded through =require.cache= beside the
user's copy, and with 19 applications and 27 windows open. =hs.ax.on= and =off=, and
=hs.application.on= and =off=, were wrapped to count calls, and restored afterwards.

| Measure                                        | Value                                  |
|------------------------------------------------+----------------------------------------|
| Starting to observe, on the first handler      | 304 ms, during which Hammerspoon 2 is busy |
| Applications and windows observed              | 19 and 27, the same as the user's copy |
| Accessibility notifications registered         | 219, in 65 calls of =hs.ax.on=         |
| Application listeners registered               | 6                                      |
| =stop()=                                       | 23 ms                                  |
| Notifications and listeners removed by =stop()= | all 219, in 46 calls, and all 6       |

The status of the user's copy was the same before and after. A run of a test file therefore
doubles the observers for its length, and costs about 0.3 s each time a test starts observing.

* stop() and start() (hammer2spoons-atg.7)

=stop()= removed every filter, =default= included, and =start()= did nothing, so after =stop()=
and =start()= =default= received no event. Nothing in the user's configuration stops and
restarts the Spoon; the test harness does. Version 0.3.6 makes =start()= put =default= back,
without handlers.

* A filter watched after windows are followed (hammer2spoons-atg.9)

A filter learned that it accepted a window only from an event about that window. A filter whose
first handler was registered while the tracker already followed a window therefore treated that
window's first change as concerning a window it never accepted, and emitted nothing: a filter
limited to one screen received neither windowRejected nor windowMoved when its window moved to
another screen. Version 0.3.7 records, when such a handler is registered, which followed windows
the filter's rules accept, without emitting anything.

* Settings (hammer2spoons-atg.8)

Every setting has a test with a value other than its default, except =applicationRetryDelays=,
which applies only when an application refuses to be observed. Two defects were found and fixed
in version 0.3.8:

1. =default= kept the =skipInDefault= array it was created with, so a new list assigned to
   =config.skipInDefault= had no effect. =default= now reads the setting each time it judges a
   window.
2. The windows an application opens as it starts were read once, and never again after
   =createdRescanDelay=: no windowCreated notification comes for them. A borderless window that
   got its title 0.3 s after opening was therefore never found. The tracker now schedules the
   later reading when an application starts while windows are observed.

The test windows can now be borderless, without a title: =fixture-windows.jxa= takes
=--borderless:<title>=, and closes such a window with a =close= command, because it has no close
button. A probe showed the user's copy tracking a titled borderless window and leaving out an
untitled one, and removing the titled one when it was closed by the command.

* A window not yet visible when its application is unhidden (hammer2spoons-atg.8)

In the full run of 2026-11-23, after =unhide()=, a test received windowUnhidden but not
windowOnScreen; every earlier run had received both. A diagnosis repeated the unhide five times
and read the window directly: 1 ms after =unhide()=, the application was still hidden and the
window not visible; by 50 ms both had changed. The tracker read the window once, about 14 ms
after =unhide()=, on the application's notification, not after =stateDebounce= as the readme
says. A read between the two changes reports the window unhidden but not visible, so not on
screen, and nothing read it again. The five attempts did not reproduce the failure; the
explanation fits the failure and the timings.

Version 0.3.9 reads the application's windows a second time, =stateDebounce= after a hide,
unhide, activation or deactivation. The event tests then passed, each event still once.
